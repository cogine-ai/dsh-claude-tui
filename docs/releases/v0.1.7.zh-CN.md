# v0.1.7 — DSH 0.2.0-rc.2 与 V4 Session

[English](./v0.1.7.md)

`0.1.7` 把包内 DeepSeek Harness 从 TUI `0.1.6` 使用的 `0.1.2-rc.1` 升级到 `0.2.0-rc.2`。保留 Claude Code `2.1.227` 交互目标，并适配新版 Harness 的 Session 回放、PTC 执行和 Provider 配置契约。

## 变化

- 回放 V4 Session 及其 tool-role 工具结果，包括最终回复、用量和计时；实时回复继续使用 Agent stream 事件。
- PTC 改用共享 Harness base bundle 提供的受沙箱约束 Node 子进程运行时。保留 `native`、`ptc`、`both` 工具模式；`code` 仍是 `ptc` 的别名。
- Provider 配置通过 `settings.describe()` 读取已解析值，打开的 Provider 界面在 `settings/document-updated` 后自动刷新。
- 生产 DSH 依赖图固定为 `0.2.0-rc.2`；外部运行时须满足 `>=0.2.0-rc.2 <0.2.1` 并通过隔离行为探针。`0.2.1-alpha` 系列不在本版本的适配范围。
- 保留 macOS 文件监听默认 1 秒轮询，以支持配置实时更新和正常退出；显式轮询设置优先。
- 镜像同一 DSH 精确标签的 1,803 个官方原始文档文件，CI 校验完整性；镜像不进入 npm tarball。

## 安装

精确选择本版本：

```bash
npx --yes --legacy-peer-deps dsh-claude-tui@0.1.7
```

需要长期使用时：

```bash
npm install --global --legacy-peer-deps dsh-claude-tui@0.1.7
dshtui
```

需要 Node.js **22.x 的 22.19+，或 24.2+**（`^22.19.0 || >=24.2.0`）。Node `24.0`、`24.1` 会在写用户 DSH Home 前被拒绝：即使显式 import 能启动顶层 CLI，固定的 Harness 子进程 runner 仍依赖 `import.meta.main`。普通 npm peer 求解和 `--legacy-peer-deps` 均有安装产物验证；`dshtui` 与 `dsh-claude-tui` 使用同一启动器。

## 升级与验证

DSH 写入 V4 Session。受支持的旧格式迁移为新文件并保留原件字节，但旧 Harness 不能读取新 generation。跨版本测试使用独立 Home，避免多个运行时并发共享同一 Home。已移除的 SQLite Session 后端需先用原运行时导出；SQLite 查询与索引是另一项服务。

最终 PR review 前已记录的检查包括：macOS arm64、Node `24.16.0` 上 179 通过、1 项 opt-in 系统剪贴板检查跳过；Node `22.23.3` 普通 npm 安装为 12 通过、1 跳过；Ubuntu 的 Node `22.19.0`、`22.22.3`、`24.2.0`、`24.14.0` 四项检查在 `58143d3` 的 [run 38099441670](https://github.com/cogine-ai/dsh-claude-tui/actions/runs/38099441670) 全部通过。后续资格结果由 [PR #21](https://github.com/cogine-ai/dsh-claude-tui/pull/21) 跟踪。

安装产物检查通过本地 Messages/Files API mock 验证 PTC 工具轮次、认证字段、退出、恢复及 V0/V3-to-V4 迁移，不代表生产 Provider 行为验收。真实系统剪贴板检查已跳过；Windows packed-TUI/ConPTY 仍未认证。

生产依赖审计报告 **14 个受影响包条目：8 个 moderate、6 个 high**，来自 `sharp@0.35.3`、`@modelcontextprotocol/client@2.0.0`、`fast-uri@3.1.7` 和内嵌 `fflate@0.8.2` 的五份公告。这些条目尚未修复；功能资格不代表安全审计清零，可利用性尚未评估。MCP 与内嵌 fflate 的修复需要处理上游精确固定的第三方版本，公告与范围见[适配记录](../harness-0.2.0-rc.2-adaptation.md#dependency-qualification-limit--依赖资格限制)。

详见[适配记录](../harness-0.2.0-rc.2-adaptation.md)、[启动器规则](../launcher-environment-compatibility.md)及 [DSH 官方发布说明](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.0-rc.2)。Registry 发布与回读核验另行记录，不与运行资格检查混为一项结果。
