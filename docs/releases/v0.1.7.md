# v0.1.7 — DSH 0.2.0-rc.2 and V4 Sessions

[简体中文](./v0.1.7.zh-CN.md)

Version `0.1.7` updates the bundled DeepSeek Harness from `0.1.2-rc.1`, used by TUI `0.1.6`, to `0.2.0-rc.2`. It retains the Claude Code `2.1.227` interaction target while adapting Session replay, PTC execution, and Provider configuration to the new Harness contracts.

## Changes

- Replays V4 Sessions and their tool-role results, including completed replies, usage, and timing. Live replies continue to use Agent stream events.
- Uses the shared Harness base bundle's sandboxed Node-process PTC runtime. The `native`, `ptc`, and `both` tool modes remain available; `code` remains an alias for `ptc`.
- Reads resolved Provider settings through `settings.describe()` and refreshes an open Provider view after `settings/document-updated`.
- Pins the production DSH graph to `0.2.0-rc.2` and accepts external runtimes only in `>=0.2.0-rc.2 <0.2.1`, after an isolated behavioral probe. The `0.2.1-alpha` series is outside this version's target.
- Retains macOS one-second file-watcher polling defaults for clean shutdown and live configuration updates. Explicit polling settings take precedence.
- Mirrors 1,803 original official documentation files from the same exact DSH tag. The mirror is checked in CI and excluded from the npm tarball.

## Install

Select this version explicitly:

```bash
npx --yes --legacy-peer-deps dsh-claude-tui@0.1.7
```

For a persistent command:

```bash
npm install --global --legacy-peer-deps dsh-claude-tui@0.1.7
dshtui
```

Requires Node.js **22.19+ in 22.x, or 24.2+** (`^22.19.0 || >=24.2.0`). Node `24.0` and `24.1` are rejected before user DSH Home writes: the pinned Harness subprocess runner requires `import.meta.main`, even when its top-level CLI could be started through an explicit import. Both ordinary npm peer resolution and `--legacy-peer-deps` have installed-artifact coverage. The `dshtui` and `dsh-claude-tui` commands use the same launcher.

## Upgrade and qualification

DSH writes V4 Sessions. Supported older generations migrate to new files while preserving predecessor bytes; older Harness versions cannot read the new generation. Use isolated Homes for cross-version testing and avoid concurrent runtimes sharing one Home. The removed SQLite Session backend requires export with its original runtime; SQLite query/index storage is separate.

Recorded checks before final PR review include macOS arm64 on Node `24.16.0` (179 passed, 1 opt-in system-clipboard check skipped), ordinary npm installation on Node `22.23.3` (12 passed, 1 skipped), and all four Ubuntu jobs on Node `22.19.0`, `22.22.3`, `24.2.0`, and `24.14.0` at `58143d3` in [run 38099441670](https://github.com/cogine-ai/dsh-claude-tui/actions/runs/38099441670). Follow subsequent qualification through [PR #21](https://github.com/cogine-ai/dsh-claude-tui/pull/21).

Installed-artifact checks use a local Messages/Files API mock for PTC tool turns, authentication fields, shutdown, resume, and V0/V3-to-V4 migration. They do not establish production-provider behavior. Real system-clipboard qualification was skipped; Windows packed-TUI/ConPTY remains unqualified.

The production dependency audit reported **14 affected package entries: 8 moderate and 6 high**, from five advisories across `sharp@0.35.3`, `@modelcontextprotocol/client@2.0.0`, `fast-uri@3.1.7`, and nested `fflate@0.8.2`. These entries remain unresolved; functional qualification does not establish a clean security audit or assess exploitability. MCP and nested fflate fixes require changing exact upstream third-party pins. See the [adaptation record](../harness-0.2.0-rc.2-adaptation.md#dependency-qualification-limit--依赖资格限制) for advisories and scope.
