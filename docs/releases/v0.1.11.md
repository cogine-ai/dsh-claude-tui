# v0.1.11 — Repair registry and npx installation

[简体中文](./v0.1.11.zh-CN.md)

Requires Node.js **24.9+** and retains DSH **0.2.2-rc.1**, the security repairs and terminal usability changes prepared for 0.1.10.

## Registry installation repair

0.1.10 passed local-tarball installation but failed after npm registry publication: npm marked unshipped transitive dependencies of bundled DSH owners as bundled when inflating the published root shrinkwrap. The subprocess helper then could not resolve `node-pty`. The `latest` tag was restored to 0.1.9 and 0.1.10 was deprecated; its GitHub Release remained a draft.

0.1.11 physically carries **all 599 required package nodes**, including 15 conflicting nested versions, from the recorded dependency graph. Every input archive is SHA-512 checked and upstream code/licenses remain unchanged apart from the existing manifest-only dependency repairs. The 584 required top-level packages are declared as bundled; 78 platform-optional packages stay exact-version dependencies for npm to select on the host.

The recorded lock is shipped as `vendor/security/runtime-lock.json` for audit and qualification, alongside the complete file/mode inventory. A root `npm-shrinkwrap.json` is not shipped, avoiding the registry inflation path. Required dependency versions and bytes are frozen by the actual bundle, rather than depending on npm honoring a partial bundle's shrinkwrap.

The installed-artifact gate now serves the **actual package through a loopback npm registry**, including real publication metadata, before installing it. The previous 0.1.10 tarball reproduces the missing-module failure through this same gate. The repaired gate checks all required package versions, the complete npm tree, production audit, native/image/MCP security, PTC, subagents, exit and Session restoration. Both ordinary peer resolution and `legacy-peer-deps` are qualified separately.

npm reapplies upstream package file allowlists when packing; 13 root `CHANGELOG.md` files are omitted by those allowlists. The published inventory covers every shipped member, and staging rejects any other upstream-file omission.

The bundled Office repair is declared by its exact version; its original commit-pinned archive URL and integrity remain in the audit record and provenance, allowing npm to validate the installed bundle.

## Install

```sh
npx --yes --legacy-peer-deps dsh-claude-tui@0.1.11
# Persistent commands:
npm install --global --legacy-peer-deps dsh-claude-tui@0.1.11
dshtui
```

Do not use 0.1.10. Publication identity, checksums and final executed verification are recorded in the [GitHub Release](https://github.com/cogine-ai/dsh-claude-tui/releases/tag/v0.1.11).

## Scope

No new DSH version, model behavior or Session format is introduced. The release retains the independently captured Claude Code 2.1.311 reference and UX fixes. Real DeepSeek production requests, OAuth/SSO, native IME, light themes and Windows ConPTY remain unqualified by these local-server tests. Cross-version Home and downgrade limits remain in effect.
