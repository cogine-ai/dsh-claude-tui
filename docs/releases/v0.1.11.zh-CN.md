# v0.1.11 — 修复 registry 与 npx 安装

[English](./v0.1.11.md)

需要 Node.js **24.9+**，继续使用 DSH **0.2.2-rc.1**，包含为 0.1.10 准备的安全修复及终端体验优化。

## 安装修复

0.1.10 的本地 tarball 安装检查通过，但发布到 npm 后，从 registry 安装会失败：npm 读取根 shrinkwrap 时，将已打包 DSH 所需的部分外部依赖误标为已随包携带，导致进程辅助器找不到 `node-pty`。已将 `latest` 恢复到 0.1.9 并弃用 0.1.10，其 GitHub Release 保持草稿。

0.1.11 实际携带记录依赖图中的 **599 个必需包节点**，包括 15 个有版本冲突的嵌套节点。每份输入归档均校验 SHA-512；除了既有的依赖清单修复，原代码和许可证不变。584 个顶层必需包明确标为随包携带，78 个平台可选包继续按精确版本声明，由 npm 根据主机选择。

依赖记录以 `vendor/security/runtime-lock.json` 随包供审计和验证，并附完整文件与权限清单。不再携带根 `npm-shrinkwrap.json`，避开出错的 registry 展开路径。必需依赖的版本和字节由实际制品固定，不依赖 npm 对部分打包 shrinkwrap 的处理。

安装包门禁现在先通过**本地 npm registry 提供真实制品和发布元数据**，再执行安装；旧 0.1.10 制品通过同一入口能够复现缺失模块。新门禁检查每个必需包的版本、完整 npm 依赖树、生产审计、原生/图片/MCP 安全、PTC、子代理、退出和会话恢复。普通 peer 求解及 `legacy-peer-deps` 分别验证。

## 安装

```sh
npx --yes --legacy-peer-deps dsh-claude-tui@0.1.11
# 持久安装：
npm install --global --legacy-peer-deps dsh-claude-tui@0.1.11
dshtui
```

请勿使用 0.1.10。发布身份、校验和及最终实测结果见 [GitHub Release](https://github.com/cogine-ai/dsh-claude-tui/releases/tag/v0.1.11)。

## 范围

未引入新的 DSH 版本、模型行为或会话格式；保留独立采集的 Claude Code 2.1.311 参考与体验修复。上述本地服务测试仍不构成真实 DeepSeek 线上请求、OAuth/SSO、原生输入法、浅色主题或 Windows ConPTY 验收。跨版本 Home 与降级限制不变。
